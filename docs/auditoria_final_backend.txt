PONTO 1 — BUG: NameError em `_parse_with_tree_sitter()`
===============================================================================

ARQUIVO:    ingestion/parser.py
LINHA:      477-478
SEVERIDADE: BAIXA — Só ocorre se tree-sitter estiver instalado E a AST
            não tiver erros de sintaxe. Em produção tree-sitter NÃO está
            instalado, então o código nunca executa.

DESCRIÇÃO:
    O método `_parse_with_tree_sitter()` possui um bloco de pós-
    processamento ao final (linhas 476-482) que referencia a variável
    `category`, mas esta variável nunca foi definida nem recebida como
    parâmetro neste método. O código é:

        for chunk in chunks:
            chunk.category = category          # <-- NameError!
            if not chunk.detected_tags:
                chunk.detected_tags = self._detect_tags(chunk.content, category)

    A variável `category` existe apenas no método `parse()` (linha 143),
    que é quem chama `_parse_with_tree_sitter()`, mas não a passa como
    argumento. Os chunks já são criados com `category=FileCategory.CODE`
    dentro do próprio `_parse_with_tree_sitter()`, portanto este bloco
    de pós-processamento é inteiramente redundante e também duplicado
    no método `parse()` (linhas 167-171), onde `category` está corretamente
    definida.

COMO CONSERTAR:
    Opção A (recomendada — remover código morto):
        Apagar as linhas 476-482 de `_parse_with_tree_sitter()`, pois:
        - O pós-processamento já é feito no método `parse()` (linhas 167-171)
        - Os chunks já têm `category` setada corretamente na criação
        - O código está dentro do fluxo tree-sitter, que NÃO executa
          em produção

    Opção B (corrigir o escopo — se quiser manter o pós-processamento):
        Adicionar `category` como parâmetro de `_parse_with_tree_sitter()`
        e passar o valor na chamada em `parse()` (linha 158):

            # Em parse(), linha 158 — adicionar category:
            chunks = self._parse_with_tree_sitter(
                source, crawl_result.relative_path, file_hash, ext,
                category  # <-- novo parâmetro
            )

            # Em _parse_with_tree_sitter(), linha 360 — adicionar parâmetro:
            def _parse_with_tree_sitter(self, source, rel_path, file_hash,
                                         ext, category):

IMPACTO DE NÃO CONSERTAR:
    Nulo. O bug nunca é acionado porque tree-sitter não está instalado
    em produção. Quando tree-sitter for instalado no futuro, o bug
    aparecerá na primeira ingestão de um arquivo sem erros de sintaxe.
    Recomenda-se a correção antes da instalação do tree-sitter.

PONTO 2 — COSMÉTICO: `Callable` não importado em storage/store.py
===============================================================================

ARQUIVO:    storage/store.py
LINHA:      114
SEVERIDADE: MÍNIMA — Não causa erro em runtime. Só detectável por type
            checkers estáticos (mypy, pyright, PyCharm).

DESCRIÇÃO:
    O método `write_callback()` usa `Callable` como type hint no
    parâmetro `fn`:

        def write_callback(self, fn: Callable, *args: Any, **kwargs: Any) -> Any:

    Porém `Callable` não consta na linha de imports:

        from typing import Any, Optional, TYPE_CHECKING

    Graças ao `from __future__ import annotations` (linha 17), todas as
    annotations são tratadas como strings e avaliadas apenas sob demanda,
    portanto o Python não tenta resolver `Callable` em tempo de execução.
    Isso evita o NameError, mas type checkers externos reportarão o erro.

COMO CONSERTAR:
    Adicionar `Callable` ao import da linha 24:

        from typing import Any, Callable, Optional, TYPE_CHECKING

IMPACTO DE NÃO CONSERTAR:
    Nenhum em runtime. Type checkers apontarão o erro, mas não afeta
    a execução. Correção leva 5 segundos.

   modo fallback/heurístico com funcionalidade reduzida. Isto é
   intencional (design) e documentado como "pontos restantes para v4.0".
