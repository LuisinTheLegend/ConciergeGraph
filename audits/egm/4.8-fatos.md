## 2. Runtime em Container (`USER concierge`, `GRAFO_LIGHTWEIGHT_MODE=true` e `.env.example`)

- **Caminhos graváveis necessários para UID não-root (`10001`):**
  1. **Diretório pai de `DB_PATH`** (`main.py:56, 242`; `storage/store.py:67-68, 86-90`; `storage/connection.py:397-400`): cria `concierge.db`, `concierge.db-wal` e `concierge.db-shm`.
  2. **`CHROMA_PATH`** (`main.py:57, 243`): `bootstrap()` executa **incondicionalmente** `os.makedirs(CHROMA_PATH, exist_ok=True)`, mesmo com `GRAFO_LIGHTWEIGHT_MODE=true` ou `GRAFO_VECTOR_BACKEND=qdrant`.
  3. **`HOME` / cache HuggingFace & Chroma ONNX:** `huggingface_hub/constants.py:159-192` usa `$XDG_CACHE_HOME/huggingface` ou `~/.cache/huggingface`; `chromadb` usa `Path.home() / ".cache/chroma/onnx_models"`.
  4. **`/tmp` (`TMPDIR`):** Arquivos temporários SQLite e `tempfile`.
- **Risco crítico `.env.example` + `pip install --no-deps .` + `docker-compose.yml`:**
  - `.env.example:35,38,79` define `GRAFO_DB_PATH=./data/concierge.db`, `GRAFO_CHROMA_PATH=./data/chroma` e `GRAFO_TRANSPORT=stdio`.
  - Se `docker-compose.yml` usar `${GRAFO_TRANSPORT:-sse}` / `${GRAFO_DB_PATH:-/app/data/concierge.db}` e existir `.env` copiado de `.env.example`, o Compose interpolará `stdio` e `./data/concierge.db`, e `PROJECT_ROOT` sob `pip install --no-deps .` apontará para `site-packages/data/` (`root`), gerando `PermissionError` para `USER concierge`. Fixar essas 3 variáveis sem `${...:-...}` em `docker-compose.yml` (como `GRAFO_HOST`/`GRAFO_PORT`) e definir defaults no `Dockerfile` elimina o problema.
- **Comportamento de `GRAFO_LIGHTWEIGHT_MODE=true` (`storage/vector_store.py:107-168, 297-302`; `core/vector_backend.py:72-74`):**
  - `EmbeddingManager.__init__` não importa `sentence_transformers` nem `torch`; `_load_model()` levanta `EmbeddingError` antes do import quando `GRAFO_LIGHTWEIGHT_MODE=true`. `ChromaVectorStore` e `QdrantVectorStore` operam em NO-OP sem abrir cliente nem baixar modelos HuggingFace.

## 3. `starlette==1.10.0` + `custom_sse_app()` (`interface/mcp_server.py`)

- **Verificação empírica de `scope["path"]` vs `scope["raw_path"]` em `TestClient` e `Uvicorn` (`seq #45`):**
  - `/health` -> `path='/health'`, `raw_path=b'/health'`
  - `/health/` -> `path='/health/'`, `raw_path=b'/health/'`
  - `/%68ealth` -> `path='/health'`, `raw_path=b'/%68ealth'`
  - `/health/../sse` -> `TestClient` (`httpx`) normaliza para `/sse`; `Uvicorn` TCP cru envia `path='/health/../sse', raw_path=b'/health/../sse'`
  - **Implicação factual:** Checar apenas `scope["path"] == "/health"` deixaria `/%68ealth` passar sem auth. Exigir também `raw_path in (None, b"", b"/health")` (e método permitido) bloqueia `/health/`, `/%68ealth`, `/health/../sse` e `POST /health` com `401`.
- **Middleware ASGI puro vs `BaseHTTPMiddleware` (`starlette/middleware/base.py:101-254`, `interface/mcp_server.py:199-231`):**
  - Na pilha Starlette (LIFO), `CORSMiddleware` é mais externo e envolve o middleware de autenticação, que envolve o `Router` (onde entra `app.add_route("/health", ...)`).
  - `BaseHTTPMiddleware` cria `anyio.create_memory_object_stream`, `create_collapsing_task_group()` e `_CachedRequest` para streams infinitos como `EventSourceResponse` (`/sse`).
  - Middleware ASGI puro (`async def __call__(scope, receive, send)`) preservando chamada dinâmica a `hmac.compare_digest` e imports tardios de `starlette.datastructures.Headers` / `JSONResponse` dentro de `custom_sse_app` foi verificado em `.venv_313`:
    - Preserva 100% o spy em `tests/test_sse_auth_hardening.py`;
    - Preserva `tests/test_governor_wiring.py::test_t1` (`governor is None`, sem `core.mcp_governor`, sem `starlette.middleware.base`, sem frameworks banidos);
    - Entrega `200 text/event-stream; charset=utf-8` chunked (`event: endpoint` + `data: /messages/...`) no `uvicorn` sem buffering, legível de forma não-travante via `http.client` `resp.readline()` (`seq #49`).
