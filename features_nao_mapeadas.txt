===============================================================================
GRAFO CONCIERGE v3.8.0 - FUNCIONALIDADES ESTRUTURADAS NÃO MAPEADAS (OCULTAS)
===============================================================================

Este documento descreve detalhadamente todas as funcionalidades estruturadas, 
métodos de negócio e operações de infraestrutura implementados nas camadas internas
do Grafo Concierge (Middleware, Storage, Services e Core) que NÃO estão expostos 
nas interfaces públicas de consumo, seja por meio da CLI (interface/cli.py) ou 
como ferramentas (tools) no Servidor MCP (interface/mcp_server.py).

-------------------------------------------------------------------------------
1. CAMADA DE MIDDLEWARE (core/middleware.py)
-------------------------------------------------------------------------------
O Middleware é a Fachada Central do sistema. Embora seja a API consumida pelas 
interfaces, alguns de seus métodos públicos não foram mapeados:

* Método: delete_project(project_uuid: str) -> None
  - Descrição: Remove fisicamente um projeto e todos os registros atrelados.
  - Comportamento: Remove de forma síncrona os embeddings vetoriais correspondentes 
    no banco de dados vetorial antes de disparar uma remoção em cascata (ON DELETE CASCADE) 
    no SQLite, deletando nós, arestas, trajetórias, commits e reference wings.
  - Motivo da Omissão: Proteção contra exclusões acidentais por agentes autônomos 
    ou execuções acidentais via terminal.

* Método: find_similar(project_uuid: str, limit: int = 5, ...) -> list[dict]
  - Descrição: Busca outros projetos no banco de dados que compartilham o mesmo 
    domínio de especialização técnica (Wings / Alas).
  - Comportamento: Consulta o ProjectIndex e compara as assinaturas das Alas 
    dos projetos para sugerir código e referências compartilháveis.
  - Motivo da Omissão: Recurso avançado planejado para colaboração multi-projeto, 
    atualmente sem interface do usuário projetada.

-------------------------------------------------------------------------------
2. CAMADA DE SERVIÇOS - JANITOR (services/janitor.py)
-------------------------------------------------------------------------------
O Janitor é um serviço autônomo de manutenção. Ele opera em background e não 
possui comandos para controle interativo externo:

* Método: run_maintenance(project_uuid: str) -> None
  - Descrição: Força a execução imediata do ciclo de otimização e saneamento.
  - Comportamento: Dispara síncronamente a validação de nós órfãos, limpeza de 
    vetores e coleta de lixo no projeto especificado.

* Método: clean_stale_data() -> None
  - Descrição: Executa a remoção de projetos inativos.
  - Comportamento: Varre a tabela de projetos e exclui projetos cujo último 
    acesso ocorreu há mais de 30 dias (configurável via `janitor_stale_threshold_days`).

* Método: reconcile_embeddings() -> None
  - Descrição: Auditoria e reconciliação vetorial de integridade física.
  - Comportamento: Varre a coleção do ChromaDB/Qdrant, compara os IDs dos vetores 
    com os IDs dos nós presentes no SQLite e deleta permanentemente qualquer 
    vetor órfão (sem nó correspondente no SQLite) para liberar memória/disco.

* Método: vacuum_sqlite() -> None
  - Descrição: Executa otimização de espaço em disco no banco relacional.
  - Comportamento: Dispara o comando PRAGMA de manutenção e o comando VACUUM, 
    reorganizando os arquivos físicos do SQLite e otimizando os índices FTS5.

-------------------------------------------------------------------------------
3. OPERAÇÕES DE BAIXO NÍVEL DO GRAFO RELACIONAL (storage/store.py)
-------------------------------------------------------------------------------
O SqliteStore esconde dezenas de métodos que gerenciam a integridade atômica 
do banco de dados relacional e da árvore AST:

* Métodos de Arestas: create_edge(), delete_edge(), update_edge_weight()
  - Descrição: Manipulação cirúrgica do fluxo direcional de arestas no Grafo.
  - Comportamento: Cria, exclui ou altera pesos e metadados de dependência de 
    chamadas (ex: chamar a Função A a partir da Classe B) de forma isolada.
  - Motivo da Omissão: O Grafo Concierge delega a criação de arestas exclusivamente
    ao parser estático da AST. Alterações arbitrárias manuais causariam desvios 
    graves na integridade estrutural da representação do código.

* Métodos de Nós: delete_node(), update_node(), cleanup_obsolete_nodes()
  - Descrição: Gerenciamento cirúrgico de nós no banco.
  - Comportamento: Remove nós específicos, altera propriedades ou faz limpezas 
    em massa de arquivos modificados/deletados no filesystem.

* Métodos de Projetos e Referências: update_project(), add_reference_wing(), remove_reference_wing()
  - Descrição: Alterações cadastrais e conexões de conhecimento.
  - Comportamento: Atualiza campos do projeto (como nome ou escopo) e adiciona 
    ou remove manualmente associações de Wings (Alas) recomendadas.

-------------------------------------------------------------------------------
4. SISTEMA DE TRAJETÓRIAS DE NAVEGAÇÃO (storage/store.py)
-------------------------------------------------------------------------------
Projetado para telemetria, este subsistema registra os passos cognitivos e de
navegação que os agentes de IA realizam ao percorrer os nós do Grafo:

* Método: create_trajectory(project_uuid: str, ...) -> int
  - Descrição: Registra uma nova sessão de navegação de raciocínio.
  - Comportamento: Armazena o ponto de entrada da sessão e metadados.

* Método: get_trajectories(project_uuid: str, ...) -> list[dict]
  - Descrição: Recupera o histórico detalhado de trajetórias cognitivas.

* Método: decay_trajectory(trajectory_id: int, new_status: str) -> bool
  - Descrição: Aplica depreciação e decaimento temporal à relevância da trajetória.
  - Motivo da Omissão: Utilizado apenas para algoritmos internos de recência 
    e Thompson Sampling. Não possui utilidade direta na CLI ou ferramentas MCP.

-------------------------------------------------------------------------------
5. INFRAESTRUTURA VETORIAL FÍSICA (storage/vector_store.py)
-------------------------------------------------------------------------------
Operações de gerenciamento direto do banco de dados vetorial de embeddings:

* Método: reset_collection() -> None
  - Descrição: Destruição total e recriação da coleção física de vetores.
  - Comportamento: Apaga o namespace de embeddings e reinicia os metadados.

* Método: count_embeddings() -> int
  - Descrição: Retorna a contagem exata de vetores na base ChromaDB/Qdrant.

* Método: get_embeddings_batch(doc_ids: list[str]) -> list
  - Descrição: Recupera vetores matemáticos puros para análise.
  - Motivo da Omissão: Operações de nível de sistema e depuração de hardware, 
    sem valor prático para agentes autônomos ou usuários finais.
