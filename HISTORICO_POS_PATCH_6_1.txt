1. AUDITORIA SÊNIOR & CORREÇÕES DE CÓDIGO (DÍVIDA TÉCNICA ZERO)
-------------------------------------------------------------------------------

A. Resolução de Memory Leak no Janitor (services/janitor.py)
   - Problema: A thread de manutenção autônoma do Janitor salvava em memória
     um relatório de manutenção (MaintenanceReport) a cada ciclo periódico (a
     cada 5 minutos), expandindo indefinidamente o tamanho da lista interna. Em
     produção ininterrupta, isso resultaria em vazamento progressivo de heap.
   - Correção: Implementado um limite superior estrito para manter apenas as
     últimas 100 execuções na memória por meio de rotação cíclica (FIFO) no
     histórico.

B. Compatibilidade do Parser Tree-Sitter (ingestion/parser.py)
   - Problema: As atualizações mais recentes do ecossistema do tree-sitter
     (versão 0.22+ e Python 3.14) removeram e depreciaram assinaturas clássicas:
       - O método `Parser.set_language(lang)` foi substituído pela atribuição
         direta de propriedade `Parser.language = lang`.
       - A inicialização da classe `Language` via capsule C depreciou o suporte a
         parâmetros do tipo int.
     Essas mudanças lançavam exceções silenciosas de AttributeError e faziam o
     sistema cair de volta no parser legacional de Regex.
   - Correção: Refatorado o carregamento dinâmico de linguagem para suportar de
     forma segura ambas as APIs (clássica e moderna). A AST nativa multilinguagem
     voltou a rodar em alta performance sem deprecation warnings ou fallbacks.

2. INFRAESTRUTURA DE DESENVOLVIMENTO, TESTES E CI/CD
-------------------------------------------------------------------------------

A. Criação de pyproject.toml e Normalização de Testes
   - Configurado o arquivo de especificação do projeto `pyproject.toml` para
     suportar a descoberta automática nativa dos testes com o comando `pytest`.
   - Normalizados os scripts de teste ativos para o padrão `test_*.py`. Os
     scripts legados com chamadas imperativas globais foram prefixados com
     `_test_*.py` para impedir interferência no pytest.
   - Suíte de 21 testes unitários e de estresse rodando perfeitamente.

B. Integração Contínua (CI/CD) via GitHub Actions
   - Criada a pipeline de automação `.github/workflows/ci.yml` para disparar
     a suíte de testes de estresse em múltiplos ambientes (SO e versões de
     Python) a cada push e pull request direcionados à branch principal.

C. Correção do check_brain.py e Limpeza do Workspace
   - Corrigido o script utilitário `tests/check_brain.py` para usar a busca
     híbrida correta com inicialização isolada de LLMAdapter via variáveis de
     ambiente em runtime.
   - Excluído o relatório temporário local `AUDITORIA_COMPLETA.txt`.
   - Atualizado o `README.md` com instruções de uso do pytest, check_brain e
     novas especificações de arquitetura da versão v3.8.2.

-------------------------------------------------------------------------------
3. EXPANSÃO DE SUPORTE AO QDRANT & QDRANT CLOUD (ESCALABILIDADE)
-------------------------------------------------------------------------------

A. Chaveamento Dinâmico de Backends no Bootstrap
   - Modificado o bootstrap em `main.py` e na CLI (`interface/cli.py`) para ler
     a variável de ambiente `GRAFO_VECTOR_BACKEND` (padrão: `chroma`). Se for
     configurada como `qdrant`, o sistema inicializa dinamicamente o
     `QdrantVectorStore` em substituição ao ChromaDB local de forma transparente.

B. Suporte a Autenticação no Qdrant Cloud (api_key)
   - Adicionada a leitura de `GRAFO_QDRANT_API_KEY` do ambiente, transmitindo
     o token de forma segura para o construtor do cliente do Qdrant. Isso
     permite plugar o Grafo Concierge nativamente em clusters de produção
     gerenciados na nuvem da Qdrant.

C. Reconciliação Bidirecional & Auto-Sincronização Natural (Auto-Sync)
   - Implementado o método `get_all_stored_node_ids` em ambos os backends
     vetoriais (Chroma e Qdrant) para recuperar todos os nós indexados no vetor.
   - Atualizado o loop de sincronização do Janitor (`_sync_vectors`) para realizar
     reconciliação bidirecional: além de remover vetores órfãos, ele calcula a
     diferença entre os nós registrados no SQLite e os presentes no vetor. Os
     embeddings faltantes são auto-gerados e sincronizados de forma totalmente
     silenciosa em background.
   - Isso garante que, se o usuário alternar o banco vetorial de Chroma para
     Qdrant no `.env`, a memória semântica seja populada automaticamente na
     primeira rodada de manutenção do sistema sem necessitar de intervenção manual.

D. Comando CLI sync-vector (Sincronização Manual Forçada)
   - Criado o novo comando utilitário na CLI `python -m interface.cli sync-vector`
     para forçar a execução imediata em lote do reconciliador semântico de todos
     os projetos (ou de um projeto individual via `--project <UUID>`), permitindo
     a migração instantânea de dados do desenvolvedor de forma controlada.
